# AI 英语能力教学系统 — 最终版系统架构设计

> 综合：需求.txt（原始需求）、deepseek 架构、doubao 架构、qwen 架构
> 原则：尊重原需求（Go+Gin+SQLite+GORM / Angular），吸收三方精华，分歧点给出明确决策，分阶段演进。

---

## 〇、设计原则（三方共识提炼）

1. **能力型、非考试型**：无刷题、无选择题，全部训练围绕「真实生活场景 + 能开口、能交流、能应用」。
2. **前后端分离**：Angular（展示） + Go Gin/GORM（业务），业务层只做 AI 调度，不直连模型推理。
3. **模块化单体起步**，模块边界清晰，可平滑演进为微服务。
4. **AI 能力统一封装**：LLM / ASR / TTS / 发音评测 / OCR 全部走中间层（统一接口、超时、重试、限流、缓存、可插拔换厂商）。
5. **流式实时语音链路**：WebSocket/SSE，绝不用 HTTP 轮询；目标「首字延迟 < 800ms」。
6. **Clean Architecture**：实体逻辑与外部依赖（数据库、大模型 API）解耦，换库、换模型不改业务代码。

## 一、技术选型（最终决策）

| 层次 | 选型 | 决策理由 |
|---|---|---|
| 前端 | Angular 17+（NgRx + PWA，Capacitor 打包移动端） | 遵循原需求；PWA 解决移动适配；不引入 Flutter 双栈（维护成本翻倍）。内置图文混排组件、多角色对话气泡、音频播放器（变速/复读） |
| 网关 | Gin（JWT、CORS、限流、WebSocket/SSE） | 原需求指定 |
| 业务 | Go + GORM（Controller → Service → Model 分层） | 原需求指定 |
| 数据库 | **SQLite 默认**（WAL + busy_timeout + cache=shared + 连接池），ORM 层留 **PostgreSQL 迁移路径**（用 GORM Dialector 抽象） | 原需求指定 SQLite，单机/私有化免运维；用户量增长后无缝迁 PG，无需改业务代码 |
| 缓存/队列 | Redis（规模化后引入） | 热教材缓存、会话状态、异步任务队列；MVP 阶段可省 |
| 对象存储 | 本地磁盘 → MinIO → 云 OSS | 音频、手写图、场景素材；存储与业务解耦 |
| 向量存储 | SQLite-vec（MVP）/ pgvector（迁移后） | RAG 检索 + 用户长期记忆 |
| 日志 | Zap + 结构化埋点 | 场景停留、卡点、跟读成功率 → 数据驱动迭代 |

## 三、内容数据来源设计（教材 & 场景资料）

### 3.0 决策：AI 大模型生成优先（主力），手工导入兜底

所有来源统一进「内容生产管线」，管线输出**统一为结构化知识点图谱 JSON**（Scene / KeyVocab / GrammarPoint / 对话脚本 / 配套练习），前端、训练模块、RAG 检索不感知内容来自哪条渠道。

**教材数据来源（按优先级）：**

| 来源 | 定位 | 机制 |
|---|---|---|
| **AI 大模型生成** | **主力（约 80%）** | 后台选择「教材版本/年级/单元」→ 编排层按 JSON Schema 生成结构化教材（课文知识点、场景对话、核心词、语法点、练习、配图描述）→ TTS 合成音频 → 入草稿库 → 人工审核后发布 |
| **PDF 导入** | 补充（教材原文/出版社电子版） | 上传 PDF → 文本提取/OCR → 章节结构半自动标定 → 转结构化图谱 → 审核 |
| **图片导入** | 补充（手机拍课本页） | 上传教材页图片 → OCR 转文本 → 同上转结构化 → 审核 |
| **JSON/Markdown 导入** | 批量/技术导入 | 直接按既定 Schema 导入，符合「教材存结构化、不存 PDF」原则 |

**日常真实场景资料来源（按优先级）：**

| 来源 | 定位 | 机制 |
|---|---|---|
| **AI 大模型生成** | **主力** | 按场景库（点餐/购物/机场/面试/校园…）批量生成：场景图文、对话脚本、词汇句型、TTS 音频、配套练习；配图用 AI 绘图生成，或场景图库兜底 |
| **手工导入** | 辅助（真实素材） | 上传真实照片、真实对话录音、文章 → 入库 → **AI 辅助打标签 + 生成配套练习** → 审核后发布 |

**统一内容生产管线（核心机制）：**

```
任意来源(LLM生成 / PDF / 图片 / JSON / 手工上传)
  → 结构化校验（JSON Schema 强约束）
  → 草稿库(Draft)
  → 管理员审核工作台（AI 初稿 + 人工把关：质量 / 版权 / 准确性）
  → 发布 → 内容库(Content Store) → 前端展示 / 训练模块 / RAG 统一取用
```

**关键约束：**
1. **AI 只产初稿，人工审核把关**——质量、版权、准确性三道防线，杜绝 AI 幻觉内容直接上线。
2. **版权合规**：AI 生成「基于教材主题的知识点 + 场景化拓展」，**不复制教材原文**；教材正文原文只能走 PDF/图片授权导入。
3. **批量生成异步化**：走任务队列，后台看进度，不阻塞操作。
4. **审核工作台**挂在后台管理模块（见 3.7 内容生成工作台）。

## 四、核心功能模块（合并三方、去重去冲突）

### 3.1 教材同步模块

**A. 教材目录初始化**
- 预置**主流教材目录模板**（内置 JSON：人教版/外研版/牛津版等 × 小学/初中/高中），人工维护保证目录准确。
- 初始化双通道（可并行）：
  1. **内置模板一键初始化**：选择教材版本 → 生成 年级→单元→课时 完整目录树。
  2. **大模型辅助生成**：输入教材名称/版本 → LLM 生成目录草稿 → 审核 → 激活。
- 目录节点状态机：`未初始化 → 待生成 → 已生成 → 已审核 → 已发布`；目录是教材骨架，**必须先于内容**；目录版本化，变更不影响已发布内容。

**B. 按 教材名称/年级/单元 拉取教材内容（AI 生成主力）**
- 触发：学生端/管理端选择「教材名称 + 年级 + 单元」→ 点击拉取。
- 后端流程：编排层组装 Prompt（教材版本上下文 + 单元主题 + JSON Schema 强约束）→ LLM 生成 → 校验 → **异步 TTS 多角色配音 + 配图生成** → 审核 → 发布。
- 缓存：已拉取内容入内容库，重复请求直接返回，不重复调 LLM。

**C. 教材内容结构（lesson_content JSON，图文并茂基础）**
```json
{
  "unit": "Unit 3 餐厅点餐",
  "dialogue": [
    {"role": "waiter",   "text": "Good evening! Can I take your order?", "audio_url": "...", "image": "..."},
    {"role": "customer", "text": "Yes, I'd like a cheeseburger, please.", "audio_url": "..."}
  ],
  "key_vocab": [{"word": "menu", "phonetic": "/ˈmenjuː/", "meaning": "菜单", "example": "...", "audio_url": "..."}],
  "grammar_points": [{"point": "Would like", "explanation": "...", "example": "..."}],
  "practice": [...],
  "images": ["..."]
}
```

**D. 图文并茂渲染（前端）**
- 内容 JSON 内嵌 images/图文混排结构 → 前端**图文混排组件**渲染（场景图 + 对话气泡 + 单词卡片 + 语法卡片）。

**E. 在线语音朗读**
- 课文/单词/句子每段均带 TTS `audio_url`；播放器支持：点击即播、**变速（0.5x~1.5x）**、**逐句复读**、单句循环、关键词高亮。

**F. 多角色对话（三种模式）**
- 对话脚本按角色拆分（waiter/customer…），**每个角色映射固定 TTS 音色**（男声/女声/童声），音色表可配。
- 模式 1 **聆听**：按角色自动分声播放（角色扮演式听力）。
- 模式 2 **分角色跟读**：用户扮演某一角色，AI 扮演其余角色，逐句跟读 + 发音评测。
- 模式 3 **AI 自由对话**：与场景角色实时开口对话（见 3.3）。
- 前端对话气泡 UI：不同角色不同头像/配色，点击气泡播放该角色音频。

### 3.2 听说读写全能力训练（核心业务）
- **听**：真实场景原声、变速播放、逐句复读、静音跟读、关键词高亮；训练"听懂语义、抓关键信息"而非选题。
- **说**：AI 真人发音领读、单句/全文跟读、无限复读；**发音评测四维评分**（准确度/流畅度/完整度/语调）+ 音素级纠错；连读、重音、弱读专项训练。
- **读**：穿透式图文阅读——点击单词行间释义、AI 依上下文生成新例句、读后 AI 开放式提问引导口语复述；分级阅读。
- **写**：手写画板 → 英文 OCR 识别 → **AI 批改（拼写/语法/句式/地道表达）** + **润色重写（保留原意、Side-by-side 对比）** + 逻辑诊断；保留手写记录对比修改前后。

### 3.3 AI 实景对话模块（差异化核心）
- 场景角色扮演：固定场景（点餐/打车/面试/海关/校园…）固定 AI 人设，模拟真实对话流程。
- 自由对话：无脚本自由开口，AI 自然应答。
- **VAD 自动触发**：用户停顿即 AI 接话（0.8s 内），用户插嘴 AI 自动闭嘴——真实对话感。
- 卡壳给 Hint 而非直接给答案；对话结束生成**沟通复盘报告**（如："你用了 3 次 I want，建议尝试 I'd like 更礼貌"）。
- 上下文记忆：单场景全程连贯；难度自适应（语速/词汇/句式随水平调整）。

### 3.4 能力画像与测评模块（去考试化）
- 四维能力雷达图（听/说/读/写），记录**能力值**而非考试分。
- 薄弱点专项训练：自动定位发音差、拼写弱、句型匮乏，推送对应场景训练。
- 阶段性能力测评：纯场景化考核（对话、朗读、写作、听力理解），无试卷。

### 3.5 间隔重复复习（遗忘曲线）
- 记录出错单词/短语，AI 判定遗忘时间，自动排入"今日任务"情景复现。

### 3.6 学习地图 / 成就系统
- 场景化 RPG 激励：完成"超市购物"解锁"生活达人"徽章；能力地图具象化。

### 3.7 后台管理模块
- 教材资源管理、场景库管理、用户管理、能力数据看板、大模型参数/API Key/能力开关配置。
- **内容生成工作台**：AI 批量生成教材/场景初稿、PDF/图片导入解析、草稿审核发布（见第三章内容生产管线）。

## 五、关键链路设计

### 5.1 教材目录初始化 & 内容拉取链路
```
管理员选教材版本
  → 内置模板一键初始化 / LLM 生成目录草稿
  → 审核 → 激活目录（年级→单元→课时）

用户选择 教材名称+年级+单元
  → POST /api/textbooks/{id}/lessons/{lessonId}/pull-content
  → 查内容库缓存（命中直接返回）
  → 编排层：Prompt(版本上下文+单元主题+JSON Schema+多角色要求) → LLM 生成
  → 校验 Schema → 入草稿库
  → 异步任务：TTS 逐角色配音 + 配图生成/选取
  → WS 通知完成 → 审核/发布
  → 前端渲染：图文混排 + 多角色对话气泡 + 音频播放器（变速/复读）
```

### 5.2 AI 实景对话（完整数据流）
```
Angular（VAD 检测用户说话结束）
  → WS 推音频 → Go 后端
  → ASR（流式转文本）
  → 编排层：当前场景 Prompt + 历史上下文 + RAG 检索语料 → LLM
  → LLM 流式输出文本分片 → 前端 SSE 边收边显
  → 同步触发 TTS → 音频分片 WS 下发 → 前端边收边播（首字 < 800ms）
  → 用户音频同时送发音评测 API → 评分回传
  → 对话结束 → AI 生成复盘报告
```

### 5.3 跟读评测链路
```
原音播放 + 逐词高亮（Forced Alignment 波形对齐）
  → 用户录音 → 发音评测（四维评分）
  → 读错片段红色高亮 + AI 自动暂停示范正确发音（音素级）
  → 结果写入能力画像 + 间隔重复队列
```

### 5.4 手写识别链路
```
Canvas 采集笔画坐标序列（非纯图片）
  → 后端图像预处理（去噪/对比度）
  → 英文专用 OCR 识别
  → LLM 拼写逻辑诊断（如 recieve → 提示 i before e 规则，而非只报错）
  → 笔顺动画引导重放正确写法
```

## 六、关键工程要点（三方补充去重）

1. **实时语音**：gorilla/nhooyr WebSocket + context 超时；SSE 收文本、WS 收音频。
2. **VAD + AEC**：前端 Silero VAD 自动断句；WebRTC AudioProcessing / RNNoise 回声消除与降噪（否则外放时 AI 声音被麦克风录回）。
3. **RAG 教材注入**：只检索当前知识点相关语料（如 Unit3-过去时-餐厅场景），不把所有教材塞 Prompt，控成本防跑题。
4. **大模型调用规范**：统一超时/重试/限流/缓存；对话、批改、内容生成分模型分参数；**HTTP Handler 内绝不同步等待 LLM**，异步化 + WS/SSE 推送。
5. **流式处理**：LLM 文本分片 → TTS 音频分片 → 边收边播。
6. **弱网降级**：自动切换文字对话模式、预加载下一句音频缓冲，禁止界面卡死。
7. **内容安全护栏**：Input/Output Moderation，RAG 强约束防幻觉编造语法规则。
8. **长期记忆**：向量库存用户画像，动态注入 Prompt（如"昨天机场场景混淆了 board/border，今天适当复习"）。
9. **日志埋点**：Zap 记录每个场景的停留时间、卡点、跟读成功率，作为迭代教学策略的唯一数据依据。
10. **Prompt 强约束（能力培养）**：例——"你是温和的英语老师，用简单词汇交流；用户出错时在下一轮用正确句子巧妙重复，不直接打断纠错"，落实"能力培养而非考试型"定位。

## 七、数据模型核心实体（GORM）

```

```

## 八、MVP 落地路径（三阶段，务实推进）

| 阶段 | 范围 | 技术要点 | 验证目标 |
|---|---|---|---|
| **Phase 1（1~2 月）** | 1 个教材单元 + AI 口语对话 + 智能跟读 | Go+Gin+SQLite(WAL)+Angular；WS 语音链路 + VAD + 流式 TTS/STT | **语音链路延迟**（>1.5s 即失败，先解决延迟再谈功能） |
| **Phase 2（3~4 月）** | 阅读、写作、手写、能力画像、复盘 | 自研 AI 编排层、RAG、发音评测接入 | 跑通"学-练-测-复盘"闭环，验证留存 |
| **Phase 3（6 月+）** | 个性化路径、多角色、间隔重复、成就系统 | 迁移 PostgreSQL+Redis、对象存储、模型微调降 Token 成本 | 规模化能力 |

## 九、最终决策摘要（分歧拍板）

1. **数据库**：SQLite 起步（WAL + 连接池优化），GORM Dialector 留 PG 迁移路径 → 尊重原需求轻量私有化，规模化了再迁 PG（吸收 doubao 主张，规避 deepseek/qwen 一上来就 PG 的运维负担）。
2. **前端**：Angular 单一技术栈 + PWA + Capacitor（不采纳 qwen 的 Flutter 双栈）。
3. **架构形态**：六层 + 模块化单体（不采纳 deepseek 的一步到位微服务化），模块边界清晰，可平滑演进。
4. **语音链路是 MVP 生死线**：VAD + AEC + 流式 + <800ms 首字（吸收 qwen 强调，deepseek/doubao 亦共识）。
